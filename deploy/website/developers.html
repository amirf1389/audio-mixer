Developers

The frameworks AmF X1 is built on, the local API its page uses, and how this website is hosted.

Frameworks and building blocks

AmF X1 is one browser page (the console) served by a small local program (the bridge) that talks to your audio drivers.

LayerTechnologyRole
ConsoleHTML, CSS, Web Audio APIMixer, EQ, dynamics, effects and meters run in the page's audio graph.
BridgeNode.js 22 LTS (bundled as a single executable)Serves the page on 127.0.0.1, lists devices and streams audio over WebSockets. No runtime dependencies beyond the audio engines.
Audio enginesPortAudio (naudiodon2), RtAudio (Audify)Open devices through ASIO, WASAPI, Core Audio, ALSA or JACK.
NativeC, C++ and Rust DSP cores, a Windows ASIO driverHeld to the same test vectors as the page's reference code.
Desktop shell (optional)ElectronA native window and tray around the same page and bridge.
MobileAndroid (Java, Jetpack Compose), iOS (Swift)The same page with an on-device engine.

Local API (127.0.0.1 only)

The bridge listens on http://127.0.0.1:8765 on your own computer and is not reachable from the network. Actions need the app's own page: other websites can read status only, never change settings or open audio streams.

MethodPathWhat it does
GET/api/statusBridge name, version and open streams.
GET/api/driversHost APIs, drivers and devices found on this computer.
GET/api/interfacesDevices grouped per physical interface, with read / write routes and fallbacks.
GET/api/licenseCurrent plan and machine code.
POST/api/license/checkChecks a key (genuine, this PC, expiry, upgrade or downgrade) without storing it.
POST/api/license/activateActivates a key.
WS/ws/input, /ws/output, /ws/duplex16-bit PCM audio streams to and from a device.

Every POST needs Content-Type: application/json and an X-Mixer-Action header naming the action:

curl -s http://127.0.0.1:8765/api/status

curl -s -X POST http://127.0.0.1:8765/api/license/check \
  -H "Content-Type: application/json" -H "X-Mixer-Action: license" \
  -d '{"key":"AMIX1.…"}'

Public update API

The vendor server publishes /update.json (a signed list of installers with SHA-256 checksums) and /releases/<file>. The app installs an update only when the signature matches the AMFB Audio key built into it.

CDN and hosting

This website is static HTML and one stylesheet. It loads no third-party scripts, fonts or CDN libraries, so there is nothing external to trust and the security policy stays strict.

Origin

nginx with HTTPS

TLS 1.2 / 1.3, HSTS, a strict Content-Security-Policy, rate limits and request size limits (deploy/nginx/keys-api.conf).

Edge

Any CDN in front

Proxy the domain through a CDN with "Full (strict)" TLS to the origin. Cache /assets/ for a year; revalidate HTML on every request.

Integrity

Versioned assets

Stylesheet URLs carry the version (?v=), so a new release is picked up at once without purging the cache.

# origin cache headers (already in the nginx config)
/assets/*   Cache-Control: public, max-age=31536000, immutable
/*.html     Cache-Control: no-cache
/update.json, /keys, /request-license   never cached by the CDN
