# AmF X1：低处理器占用率的直播工具

本指南介绍了如何在几乎不占用处理器资源的情况下，将 AmF X1 与 TikTok LIVE Studio 或 OBS Studio 等直播软件同时运行。本指南适用于 Windows 系统上的 AmF X1 1.24.0.5 版本。

## 是什么让处理器占用率保持在较低水平
- 没有输入的声道将被跳过。仅传输静音且未插入任何音频效果的声道不会消耗任何处理时间。
- 界面会自动变慢。当您在其中操作时，它每秒刷新30次；当其他程序处于前台时，每秒刷新4次；当它被最小化时，每秒刷新1次。声音播放速度始终保持不变。
- 当控制台处于前台时，ECO 模式会将重绘频率减半。
- 音频线程在处理器的快速核心上运行，当另一个程序处于前台时，该接口会被标记为后台任务。
- 缓冲区越大，工作块的数量就越少，每个块的规模也就越大。缓冲区大小范围为 32 到 8192 个采样点。

## 在我们的测试机上测得

该控制台会在自检过程中测量自身资源占用情况。在我们的测试机上（Linux系统，无显卡，仅计算一个处理器核心），整个程序在前台运行时占用约7%的核心资源，在后台运行时（位于另一个程序之后）占用约5%，最小化时占用约4%。

这些数据来自那台机器。您的计算机显示的数据可能会有所不同。我们尚未将其与其他产品进行比较。我们尚未在运行 TikTok LIVE Studio 时，在 Windows 系统上对其进行过测试。

## 准备进行直播
- 打开“工具”菜单，选择“实时模式”。麦克风通道将应用以下处理链：降噪、自动麦克风均衡器、电平调节器和峰值消除器。
- 主音量被限制在满量程以下3 dB，以确保音频流不会出现削波。
- 看门狗已启用。如果声卡停止工作，控制台会自动重新启动声音。
- 该窗口仅显示带有电平表和静音按钮的“LIVE”屏幕。若要退出该窗口，需输入控制台PIN码，因此访客无法更改混音设置。
- 若要单独启动“实时模式”，请在“工具”菜单中开启“自动实时”功能。当打开直播程序时，“实时模式”即会启动。
- 在流媒体程序中，将 AmF X1 的声音输出设为音频源。

## 如何以最少的处理能力运行
- 直播时将控制台最小化。这样它就会每秒刷新一次。
- 请使用 512 或 1024 个样本的缓冲区。仅当您通过调音台监听自己的声音时，才应使用较小的缓冲区。
- 仅在需要效果的声道上应用效果。
- 在将窗口最小化之前，请先关闭带有大型动态显示内容的页面，例如分析器。

## 极限
- 较大的缓冲区会增加延迟。在 8192 个采样点和 48 kHz 的情况下，一个数据块的持续时间约为 171 毫秒。
- 在依赖该锁之前，请先在“ACCESS”页面上设置您自己的PIN码。该程序的所有副本中，出厂默认PIN码均相同，因此无法提供任何保护。
- 自动麦克风均衡器通过测量人声来校正音色。这属于信号处理，而非机器学习。
